# سامانهٔ قیمت‌گذاری رقابتی هوشمند — sgeooole / ekgkala (نسخهٔ ۴.۲.۰)

موتور و پنل قیمت‌گذاری رقابتی برای فروشگاه `sgeooole` (`ekgkala`): قیمت رقبا را از **ترب** (از طریق `torob-mcp`) می‌خواند، کارت و پیشنهادهای معتبر را تشخیص می‌دهد، با رعایت **کف سود قطعی** قیمت پیشنهادی می‌سازد، یک ناظر (SubQ SystemOne) و در صورت نیاز یک مدل زبانی مکمل آن را وارسی می‌کنند و نتیجه را یا خودکار یا پس از تأیید انسان به فروشگاه می‌فرستد.

هدف نسخهٔ ۴.۲.۰: **کمترین خطای قیمت نسبت به رقبا، بدون اینکه کالای اشتباه یا پیشنهاد غیرقابل‌خرید قیمت را منحرف کند** — و هر ادعای بهبود با اندازه‌گیری (قبل/بعد، بازهٔ اطمینان، ablation) همراه است. ⚠️ اندازه‌گیری‌ها روی شبیه‌ساز بازارند؛ راستی‌آزمایی روی دادهٔ واقعی با پروتکل `docs/EVALUATION.md` §۸ انجام می‌شود.

## معماری

```
ترب ──► torob-mcp (پورت ۳۰۰۵) ──► موتور قیمت‌گذاری + پنل (Next.js، پورت ۳۰۵۰، PostgreSQL)
                                     │ تطبیق محصول v2 → تخمین‌گر قیمت v2 → ناظر SystemOne → (LLM مکمل، اختیاری)
                                     ▼
                  اعمال خودکار (اعتماد بالا) / صف بازبینی انسان
                                     │  POST /api/products/pricing-sync  +  X-Pricing-Secret
                                     ▼
              بک‌اند فروشگاه (ekgkala-backend: Express + MongoDB) ──► وب‌سایت
```

- **کف سود قطعی** (`hardFloorPrice`) و گارد «هرگز زیر قیمت خرید» در تمام مسیرها دست‌نخورده‌اند؛ هیچ قیمتی زیر کف ساخته نمی‌شود (در ۲۳٬۴۰۰ تصمیمِ ارزیابی: نقض کف = ۰).
- قیمت خرید/کف/تامین‌کننده به‌طور پیش‌فرض **به هیچ سرویس خارجی** (LLM/SubQ) نمی‌رود و API عمومی فروشگاه هم آن‌ها را برنمی‌گرداند (`docs/SECURITY_AND_PRIVACY.md`).

## نصب و اجرای سریع

```bash
cp .env.example .env         # مقدارها را پر کنید (دست‌کم DATABASE_URL, SGEOOOLE_PRICING_SECRET, ADMIN_PASSWORD, CRON_SECRET)
docker compose -f docker-compose.postgres.yml up -d     # اختیاری: PostgreSQL محلی؛ رمزِ نمونهٔ فایل compose را عوض کنید و همان را در DATABASE_URL بگذارید
npm install
npm run db:migrate           # مهاجرت‌های دیتابیس
npm run mcp:serve:vendor     # در ترمینال جدا: torob-mcp (نسخهٔ داخل پروژه، همان که در تولید اجرا می‌شود) روی ۳۰۰۵
npm run dev                  # پنل: http://localhost:3050
```

تولید: `npm run build` سپس `pm2 start ecosystem.config.cjs` (هر دو سرویس `torob-mcp` و `sgeooole-pricing`؛ فایل `.env` را همان فایل می‌خواند). اجرای دوره‌ای: `GET /api/scheduler/tick` با هدر `Authorization: Bearer $CRON_SECRET` را با cron بزنید.

> `npm run mcp:serve` (قدیمی) بستهٔ npm با نسخهٔ `0.1.2` را می‌گیرد، نه نسخهٔ داخل پروژه (`vendor/torob-mcp`، ۰.۵.۹) که قفل چالش ۴۹۰، `POST /reset` و رلهٔ `TOROB_API_BASE` را دارد و در تولید اجرا می‌شود. برای یکسان بودن توسعه و تولید از `mcp:serve:vendor` استفاده کنید؛ این اسکریپت `.env` را نمی‌خواند، پس رله را در همان فرمان بدهید: `TOROB_API_BASE=https://... npm run mcp:serve:vendor`.

### نکتهٔ ترب (مهم)
ترب از IP دیتاسنتر خارج ایران `HTTP 490` (چالش ربات) می‌دهد؛ بدون سرور داخل ایران یا یک **رلهٔ تحت کنترل خودتان** (`TOROB_API_BASE`، آدرس مطلق `https`) هیچ داده‌ای نمی‌رسد و همهٔ بهبودهای تخمین‌گر بی‌اثر می‌شود. رله فقط وقتی کمک می‌کند که روی شبکه‌ای باشد که مسدود نیست؛ حتی برخی آدرس‌ها به‌کلی رد می‌شوند و هیچ تنظیمی آن را برطرف نمی‌کند (اندازه‌گیری‌ها: `vendor/torob-mcp/CHANGELOG.md`، نسخهٔ ۰.۵.۹).

## ارتقا از ۴.۱.x — قبل از استقرار بخوانید

1. **کلید همگام‌سازی:** `SGEOOOLE_PRICING_SECRET` را (`openssl rand -hex 32`) در **هر دو** سرویس بگذارید؛ وگرنه فروشگاه `503` می‌دهد و قیمت‌گذاری خودکار متوقف می‌ماند (قیمت‌های فعلی بدون تغییر می‌مانند). `ekgkala-backend/PRICING_SECURITY_4.2.0.md`.
2. **تخمین‌گر v2 برای پروفایل‌های موجود روشن می‌شود.** برای ماندن روی منطق قیمت‌گذاری ۴.۱.۲: `{"estimator":{"mode":"legacy"}}` را با `scripts/apply-estimator-config.cjs` اعمال کنید (`docs/ESTIMATOR_V2.md` §۱۱). تطبیق‌دهندهٔ v2 با آن هم فعال می‌ماند.
3. **تطبیقِ سخت‌گیرانه‌تر:** در روزهای نخست کالاهای بدون کد مدل و موارد مبهم بیشتری به صف بازبینی می‌روند.
4. **توصیه:** هفتهٔ اول را در «حالت سایه» (`auto_apply=false`) اجرا کنید و ممیزی تصادفی انجام دهید؛ سپس آستانهٔ اعتماد را با دادهٔ واقعی تنظیم کنید (`docs/EVALUATION.md` §۸).

## پیکربندی مهم

| متغیر | معنا |
| :-- | :-- |
| `DATABASE_URL` | PostgreSQL موتور |
| `SGEOOOLE_API_URL`، `SGEOOOLE_PRICING_SECRET` | آدرس بک‌اند فروشگاه (localhost/https) و کلید مشترک همگام‌سازی |
| `TOROB_MCP_URL`، `TOROB_API_BASE` | سرور MCP و (اختیاری) رلهٔ ترب |
| `ADMIN_PASSWORD`، `AUTH_SECRET`، `CRON_SECRET` | قفل پنل و کرون — **بدون `ADMIN_PASSWORD` همهٔ پنل باز است** |
| `SUBQ_API_KEY`، `AI_API_KEY` | ناظر SystemOne و LLM مکمل (اختیاری؛ بدون توکن، ناظر محلی کار می‌کند) |

پیش‌فرض‌های تصمیم‌گیری (کف سود، پله‌های undercut، آستانه‌ها) در «تنظیمات» پنل/پروفایل قیمت‌گذاری‌اند؛ بخش `estimator` (تخمین‌گر v2) فقط با اسکریپت `estimator:apply` تغییر می‌کند، نه با `POST /api/profiles` (آن، سفارشی‌سازی‌های دیگر پروفایل را پاک می‌کند).

## محدودیت‌های شناخته‌شده (خلاصه)

- اعداد بهبود از شبیه‌ساز می‌آیند؛ برچسب انسانی و ترب واقعی هنوز در حلقه نیستند (`docs/EVALUATION.md` §۸–۹).
- v2 در بسیاری از سناریوها بیشتر «حاشیه می‌بخشد»؛ در `volatile`/`stress_all` مجموع انحراف بهتر نشد؛ `thin` و `wide` بهبود معنادار نشان ندادند.
- تطبیق: کالای عمومی بدون کد و لنزِ متفاوت با کد یکسان هنوز می‌توانند خودکار تأیید شوند (سیاست آگاهانه؛ `docs/MATCHER_V2.md` §۱۰).
- پنل بدون `ADMIN_PASSWORD` باز است.
- `typecheck` کامل در محیط ساخت این بسته اجرا نشد (رجیستری npm در دسترس نبود)؛ فقط `src/lib` و `src/db` با جایگزین‌های drizzle/pg بررسی شدند (`docs/EVALUATION.md` §۹). پیش از استقرار `npm install && npm run verify` را بزنید.
