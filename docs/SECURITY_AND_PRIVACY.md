# امنیت و حریم‌خصوصی داده (نسخهٔ ۴.۲.۰)

> هدف: قیمت خرید، کف سود و تامین‌کنندگان **محرمانه‌ترین داده‌های فروشگاه‌اند**. رقیبی که کف ما را بداند می‌تواند دقیقاً یک پله بالای آن بایستد یا ما را به کف بکشاند.
> این سند می‌گوید این داده‌ها از کجا می‌توانستند بیرون بروند، چه چیزی بسته شد، و **چه چیزی هنوز در مسئولیت استقرار شماست**.

---

## ۱. داده‌های محرمانه

| داده | کجا نگه‌داری می‌شود |
| :-- | :-- |
| `costPrice` (قیمت خرید/تمام‌شده) | PostgreSQL پنل + سند `Product` در MongoDB فروشگاه |
| `hardFloorPrice` (کف قطعی فروش) | هر دو + `pricingMeta.hardFloorPrice` |
| `supplierQuotes` (نام تامین‌کننده + قیمت خرید) | هر دو |
| `effectiveCostPrice`, `replacementCost` (محاسبه‌شده) | فقط حافظهٔ موتور و گام‌های لاگِ داخلی |

## ۲. مسیرهای خروج داده و اقدام

### ۲-الف) مدل زبانی مکمل (LLM) — `src/lib/ai/review-payload.ts`

**مشکل:** نسخهٔ پیشین `reviewDecisionWithAI` قیمت تمام‌شده و متن دلایل بازبینی را مستقیم به API شخص ثالث (`AI_BASE_URL`) می‌فرستاد؛ دلایل بازبینی اغلب شامل اعدادی مثل «کف سود ۱٬۲۳۴٬۰۰۰ است» بود.

**اکنون (دفاع در عمق):**
1. هیچ قیمت خرید/تمام‌شده/کف/حاشیه‌ای در payload نیست.
2. دلایل بازبینی که به موضوع هزینه/کف/حاشیه/همکار/تامین اشاره دارند **کامل حذف** می‌شوند (فهرست الگوها در `CONFIDENTIAL_TOPIC`).
3. هر عدد **برابر با** تمام‌شده/کف/قیمت خرید پایه (با هر قالب رقم: لاتین/فارسی/عربی‌هندی، با هر جداکنندهٔ هزارگان، و معادل ریالی ×۱۰) در بقیهٔ متن‌ها با «[محرمانه]» جایگزین می‌شود. تطبیق «برابری دقیق مقدار» است، پس اعداد بازار که اتفاقاً نزدیک‌اند سالم می‌مانند.
4. متن‌های بیرونی (نام فروشندگان ترب) نامطمئن‌اند: کاراکترهای کنترلی/جهت‌دهی حذف و طول محدود می‌شود (مقابلهٔ ساده با تزریق پرامپت).
5. LLM فقط **مشاور** است: حکم `adjust` همیشه تصمیم را به بازبینی می‌برد و پیشنهادِ زیر کف/تمام‌شده در `runner.ts` «مردود» ثبت می‌شود؛ LLM هرگز قیمتی را خودش اعمال نمی‌کند. فراخوانی فقط وقتی انجام می‌شود که اعتماد موتور کمتر از `ai.reviewBelowConfidence` (پیش‌فرض ۰٫۷۲) باشد.

**باقی‌مانده (آگاهانه):** قیمت نهایی پیشنهادی و سقف (`proposedFinalPrice`, `ceilingPrice`) به LLM می‌روند، چون همان قیمتی است که روی سایت عمومی نمایش داده می‌شود. اگر قیمت «روی کف» ایستاده باشد، LLM فقط همان قیمت را می‌بیند؛ نسبت آن با کف/هزینه هرگز اعلام نمی‌شود. اگر این هم برایتان قابل‌قبول نیست، `ai.enabled=false` کنید (موتور بدون آن کار می‌کند).

### ۲-ب) ناظر SubQ SystemOne

- پیش‌فرض `supervisor.shareCostWithApi = false`: به API فقط نتیجهٔ «گارد سود» می‌رود — `ProfitGuard: PASSED | FAILED | UNKNOWN_COST` که **محلی و قطعی** محاسبه شده؛ پرسش گیت سود هم بازنویسی می‌شود تا از API هزینه نخواهد.
- اگر `true` شود، `SupplyCost`، `HardFloor` و `Source` به API می‌رود. فقط در صورتی که API را کاملاً مورد اعتماد می‌دانید.
- بدون توکن (`SUBQ_API_KEY` خالی) ناظر کاملاً محلی کار می‌کند و هیچ تماس بیرونی ندارد.

### ۲-پ) API عمومی فروشگاه (`ekgkala-backend`)

**مشکل:** `GET /api/products`، `/api/products/:id`، `/api/products/code/:code` (و `?skipDiscount=true`) کل سند محصول را برمی‌گرداندند؛ یعنی هر بازدیدکننده می‌توانست `costPrice`، `hardFloorPrice` و `supplierQuotes` را بخواند.

**اکنون (سه لایه):**
1. `middleware/hideInternalPricingFields.js` روی `/api` (در `server.js`): این کلیدها را در هر عمقی از هر پاسخ JSON حذف می‌کند (`costPrice, hardFloorPrice, supplierQuotes, replacementCost, effectiveCostPrice`). اگر پاک‌سازی خطا بدهد، داده خام فرستاده نمی‌شود (۵۰۰).
2. مدل `Product`: این سه فیلد `select:false`‌اند.
3. پایپ‌لاین لیست محصولات (`productListingService`) آن‌ها (و `pricingMeta.hardFloorPrice`) را صریحاً `$project` می‌کند.

فیلدهای غیرمحرمانهٔ `pricingMeta` (مثل `exactFloorPrice`، `badgeTheme`) که منطق کف قطعی و نمایش به آن‌ها نیاز دارد دست‌نخورده می‌مانند.

**بررسی سازگاری:** در سورس‌های `admin/` (۱۱۸ فایل) و `frontend/` (۳۷۱ فایل) موجود در بستهٔ شما هیچ ارجاعی به این فیلدها نیست. تنها مسیر داخلیِ `POST /api/products/pricing-sync` آن‌ها را لازم دارد و صریحاً `select('+costPrice +hardFloorPrice +supplierQuotes')` می‌کند. اگر در نسخهٔ مستقر شما کد دیگری آن‌ها را می‌خواند، همان مسیر را با `req.__allowInternalPricingFields = true` (پشت احراز هویت مدیر) استثنا کنید.

**⚠ اسناد موجود در دیتابیس تغییر نکرده‌اند** — فقط از دید API پنهان شده‌اند. اگر پیش‌تر این داده‌ها از API عمومی قابل‌خواندن بودند، فرض کنید ممکن است **افشا شده باشند** (بازهٔ زمانی را از لاگ nginx بررسی کنید) و در صورت حساسیت، کف/تامین‌کنندگان را بازنگری کنید.

### ۲-ت) مسیر ایمپورت

`scripts/import-mongo-products.cjs` اکنون `.select("+costPrice")` می‌کند (چون فیلد `select:false` است؛ بدون آن قیمت خرید همه ۰ ایمپورت می‌شد و کالاها «بی‌قیمت‌خرید» رفتار می‌کردند).

### ۲-ث) پایگاه دادهٔ تصمیم‌ها (`price_decisions.steps`)

گام‌های لاگِ موتور (مثل گام `sourcing`) مقادیر `effectiveCostPrice`/`hardFloorPrice` را برای نمایش به مدیر دارند. این‌ها فقط داخل PostgreSQL پنل‌اند و از طریق خود پنل (پشت `ADMIN_PASSWORD`) دیده می‌شوند. دادهٔ جدیدِ ۴.۲.۰ (برای بازتنظیم اعتماد) فقط **احتمال‌ها و مقادیر بولی** است (`pRight`, `pNoneValid`, `floorBound`, …) — هیچ مبلغی ندارد.

## ۳. راز مشترک همگام‌سازی قیمت (`X-Pricing-Secret`)

**مشکل پیشین:** `if (expectedSecret && incoming !== expectedSecret) → 401` یعنی اگر متغیر محیطی تنظیم نشده بود شرط **اصلاً بررسی نمی‌شد** و اندپوینتی که قیمت فروش و کمپین‌ها را تغییر می‌دهد برای همهٔ اینترنت باز بود (fail-open)؛ مقایسهٔ `!==` هم زمان‌ثابت نبود.

**اکنون** (`utils/pricingSyncAuth.js`، آزمون: `tests/pricing-sync-auth.test.cjs`):
- **fail-closed:** بدون کلید پیکربندی‌شده (یا با مقدار نمونه‌ای مثل `CHANGE_ME`, `secret`, `password`) پاسخ `503` می‌دهد.
- مقایسهٔ **زمان‌ثابت** (SHA-256 دو طرف + `crypto.timingSafeEqual`).
- تنها راه عبور بدون کلید: `NODE_ENV` برابر `development`/`test` **و** `PRICING_SYNC_ALLOW_UNAUTHENTICATED=true`؛ در production هرگز.
- کلید کوتاه‌تر از ۲۴ نویسه هشدار می‌دهد.

**چرخش کلید (Rotation):**
```bash
openssl rand -hex 32            # کلید تازهٔ ۶۴ نویسه‌ای
# همان مقدار را در هر دو سرویس بگذارید:
#   موتور قیمت‌گذاری  (.env)           : SGEOOOLE_PRICING_SECRET=...
#   بک‌اند فروشگاه   (.env)           : SGEOOOLE_PRICING_SECRET=...   (یا STORE_WEBHOOK_SECRET)
# سپس هر دو را ری‌استارت کنید (پنجرهٔ کوتاه ناهماهنگی ⇒ فقط 401 در همگام‌سازی؛ هیچ قیمتی اشتباه نمی‌نشیند).
```
اگر برای کانکتور فروشگاه در پنل موتور (جدول `store_connectors`) خودِ `apiKey` را ذخیره کرده‌اید، آن مقدار بر `.env` اولویت دارد (`src/lib/store/connectors.ts`)؛ آن را هم هم‌زمان به‌روز کنید.

**امنیت انتقال:** بدنهٔ همین درخواست (`POST /api/products/pricing-sync`) خودش `costPrice` و `hardFloorPrice` را برای گارد کف قطعیِ فروشگاه حمل می‌کند. پس `SGEOOOLE_API_URL` باید `localhost`/شبکهٔ داخلی یا **https** باشد؛ روی http و اینترنت عمومی، هم راز و هم قیمت خرید آشکار می‌رود.

## ۴. پنل وب موتور (وضعیت موجود، تغییرنکرده)

**⚠ اگر `ADMIN_PASSWORD` تنظیم نباشد، همهٔ صفحات و APIهای پنل باز است** (طراحی پیشین؛ پنل خودش هم هشدار می‌دهد). پنل قیمت خرید و کف را نمایش می‌دهد؛ پس در production حتماً `ADMIN_PASSWORD` (و ترجیحاً `AUTH_SECRET` جدا) و `CRON_SECRET` قوی تنظیم کنید و پنل را پشت شبکهٔ خصوصی/VPN/allow-list بگذارید.

## ۵. چک‌لیست استقرار

- [ ] `SGEOOOLE_PRICING_SECRET` در هر دو سرویس، ≥ ۲۴ نویسهٔ تصادفی، غیر از `CHANGE_ME`
- [ ] `ADMIN_PASSWORD`, `AUTH_SECRET`, `CRON_SECRET` تنظیم‌شده
- [ ] رمز نمونهٔ PostgreSQL در `docker-compose.postgres.yml` (`POSTGRES_PASSWORD`) عوض شود و با `DATABASE_URL` یکی باشد (پورت فقط روی `127.0.0.1` باز است، ولی رمز نمونه نباید ماندگار شود)
- [ ] `SGEOOOLE_API_URL` فقط `http://127.0.0.1:…`/شبکهٔ داخلی یا `https://…` (بدنهٔ همگام‌سازی شامل قیمت خرید و کف است)
- [ ] `supervisor.shareCostWithApi` = `false` (پیش‌فرض)؛ اگر LLM نمی‌خواهید `ai.enabled=false`
- [ ] لاگ nginx فروشگاه را برای دسترسی‌های گذشته به `/api/products` بررسی کنید (افشای احتمالی پیشین)
- [ ] `npm test` (موتور) و `node --test tests/pricing-sync-auth.test.cjs tests/public-api-secrets.test.cjs` (فروشگاه) پیش از انتشار
- [ ] `TOROB_API_BASE` (در صورت نیاز) فقط یک آدرس **https** از رلهٔ تحت کنترل خودتان باشد؛ رله تمام پرس‌وجوهایتان را می‌بیند و روی شبکهٔ مسدودشده سودی ندارد

## ۶. آنچه این نسخه **انجام نمی‌دهد**

- رمزنگاری ستونی قیمت خرید در پایگاه داده (نیاز به مدیریت کلید دارد)؛
- پنهان‌سازی `pricingMeta.confidence`/`decisionId`/رتبه‌ها در خروجی عمومی (هنوز در پاسخ فروشگاه می‌آیند؛ حساس نیستند ولی اطلاعات «ما چقدر مطمئن‌ایم» را می‌دهند — اگر نمی‌خواهید، به `SECRET_KEYS` در میان‌افزار اضافه کنید)؛
- حسابرسی/ثبت دسترسی به فیلدهای محرمانه؛
- محدودسازی نرخ (rate-limit) اندپوینت `pricing-sync` (احراز هویت قوی است، ولی بدون محدودیت نرخ).
- مقایسهٔ `CRON_SECRET` در `/api/cron` و `/api/scheduler/tick` هنوز با `!==` انجام می‌شود (برخلاف `pricing-sync` زمان‌ثابت نیست)؛ عملاً از راه شبکه قابل‌سوءاستفاده نیست ولی برای یکدستی می‌توان با `timingSafeEqual` اصلاح کرد.
