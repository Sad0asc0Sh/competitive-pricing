# منطق سامانه قیمت‌گذاری هوشمند (مبتنی بر ترب)

> نسخه ۱ — این سند «قرارداد رفتاری» سیستم است؛ هر تغییر منطق ابتدا این‌جا ثبت و سپس در کد پیاده می‌شود.

## ۱. هدف

فروشگاهی که **بدون دخالت انسان** قیمت‌هایش را با بازار ایران (معیار: ترب) هماهنگ می‌کند، به‌طوری‌که:

1. قیمت **کف بازار ولی منصفانه و اصولی** باشد (نه کف اشتباهِ فروشگاه‌های آپدیت‌نشده).
2. سود هرگز زیر حداقل تعریف‌شده نرود.
3. قیمت رقابتی نهایی همیشه به شکل **قیمت اصلی + تخفیف** (لحظه‌ای / منتخب‑شگفت‌انگیز) نمایش داده شود.
4. خطای قیمت‌گذاری نزدیک به صفر باشد: هر تصمیم مشکوک به جای اعمال، به صف بازبینی می‌رود.
5. همه‌چیز **ماژولار** باشد: منبع داده، الگوریتم، کمپین، کانکتور فروشگاه و زمان‌بند مستقل از هم.

## ۲. معماری ماژولار

```
┌────────────┐   ┌──────────────┐   ┌────────────────┐   ┌──────────────┐   ┌─────────────┐
│  Sources   │ → │ Pricing Core │ → │ Discount/Camp. │ → │ Guards/Apply │ → │ Store Conn. │
│ torob/mock │   │ (pure funcs) │   │ flash/featured │   │ review queue │   │ woo/webhook │
└────────────┘   └──────────────┘   └────────────────┘   └──────────────┘   └─────────────┘
       ↑                 ↑                                                        ↑
   humanize.ts       PricingProfile (JSON قابل تنظیم)                        Scheduler
   ai/client.ts      per‑product override                                     (interval / cron)
```

| ماژول | مسیر | مسئولیت |
|---|---|---|
| منابع | `src/lib/sources/*` | آداپتور ترب (API → HTML → AI)، شبیه‌ساز، ورود دستی، لایه انسان‌نما |
| هسته قیمت | `src/lib/pricing/*` | فیلتر، حذف پرت، تجمیع، استراتژی، محافظ، تخفیف، اعتماد — **بدون IO** |
| کمپین | `src/lib/pricing/campaigns.ts` | نگاشت تخفیف به برچسب لحظه‌ای/منتخب بر اساس بازه، ساعت، روز، دسته، اولویت |
| AI | `src/lib/ai/client.ts` | استخراج از HTML، نظر دوم روی تصمیم‌های کم‌اعتماد |
| سرویس | `src/lib/services/*` | اجرا، ذخیره تصمیم، اعمال، زمان‌بند |
| کانکتور | `src/lib/store/connectors.ts` | ووکامرس / وب‌هوک؛ ارسال `regular_price` و `sale_price` |

## ۳. خط لوله تصمیم (Pipeline) — قدم به قدم

### قدم ۰ — استعلام منبع
- آداپتور ترب سه لایه دارد: **API عمومی JSON** (`api.torob.com/v4/base-product/details/?prk=`) → **HTML + `__NEXT_DATA__`** → **استخراج با AI** از متن صفحه.
- لایه انسان‌نما: تأخیر تصادفی ۱.۵ تا ۴.۵ ثانیه per‑host، چرخش User‑Agent، هدرهای مرورگر، retry با backoff.
- خروجی نرمال: `{shopName, price, lastChangedAt, isAd, inStock, url}` + `totalSellerCount`.

### قدم ۱ — اعتبار لیستینگ (مسئله «ادغام‌نشده‌ها»)
- اگر `totalSellerCount < minSellerCount` (پیش‌فرض ۵) → لیستینگ به‌عنوان معیار قابل اعتماد نیست → **تصمیم به بازبینی می‌رود**.
- دلیل: ترب برای بعضی فروشنده‌ها لیستینگ جدا می‌سازد؛ یک فروشنده حرفه‌ای با لیستینگ ۲ نفره نباید معیار ما شود.

### قدم ۲ — فیلترهای اعتبار داده (مسئله «۵ سایت اول آپدیت نیستند»)
حذف می‌شوند:
- قیمت صفر/نامعتبر
- فروشگاه خودمان (تا خودمان را دنبال نکنیم!)
- لیست سیاه
- آگهی تبلیغاتی (`is_adv`)
- ناموجود
- **قدیمی‌تر از `maxOfferAgeDays` (پیش‌فرض ۷ روز)** بر اساس «آخرین تغییر قیمت» — این همان فیلتری است که فروشگاه‌های ارزانِ آپدیت‌نشده را از معادله بیرون می‌اندازد.

### قدم ۳ — حذف داده‌های پرت (دو مرحله‌ای)
1. **باند سخت**: هر قیمتی بیش از `hardBandPct` (۲۵٪) دورتر از میانه → حذف.
2. **آماری**: روی باقی‌مانده، IQR (`Q1 − 1.5·IQR , Q3 + 1.5·IQR`) یا MAD (`median ± 3·1.4826·MAD`).

چرا دو مرحله؟ اگر چند فروشگاه با هم قیمت خیلی پایین (اشتباه/کالای غیراصل) داشته باشند IQR به تنهایی گاهی آنها را نگه می‌دارد؛ باند سخت جلوی این را می‌گیرد. اگر نمونه‌ها کمتر از `minSamples` باشد فقط باند سخت اجرا می‌شود.

### قدم ۴ — وزن‌دهی و تجمیع → «قیمت مرجع بازار»
- وزن تازگی: `w = 0.5 ^ (ageDays / halfLife)` (نیمه‌عمر ۳ روز) → قیمت امروز وزن ۱، قیمت ۳ روز پیش وزن ۰.۵.
- مرجع = میانگین وزنی (پیش‌فرض) / میانه / میانگین بریده.
- خروجی: کف معتبر، میانه، میانگین، مرجع، پراکندگی (CV).

### قدم ۵ — استراتژی رتبه اول
```
gap = (reference − lowestValid) / reference
if gap ≤ maxGapPct (3%):       target = lowestValid − max(undercutAmount, lowestValid·undercutPct)
elif fallbackToReference:      target = reference        # کف مشکوک است، دنبالش نرو
else:                          target = lowestValid
```
یعنی فقط وقتی کف بازار «معتبر و نزدیک به اجماع» است برای رتبه اول می‌جنگیم؛ اگر یکی ۱۰٪ پایین‌تر از همه بود، احتمالاً اشتباه است و ما به مرجع می‌چسبیم.

### قدم ۶ — محافظ‌ها (خطای نزدیک صفر)
1. **کف سود**: `price ≥ ceil(cost × (1 + minMargin%))`؛ اگر برخورد کرد → قیمت روی کف سود + **بازبینی**.
2. **سقف تغییر در هر اجرا**: اگر `|Δ| > maxChangePctPerRun` (۱۵٪) → قیمت به سقف محدود + **بازبینی**. (جلوی جهش ناشی از داده معیوب را می‌گیرد.)
3. گرد کردن به گام (۱۰۰۰ تومان) و قیمت روانی (x900 / x000).

### قدم ۷ — ساخت قیمت اصلی + تخفیف
- `final` = خروجی قدم ۶ (قیمت واقعی فروش).
- `base` (قیمت اصلی/خط‌خورده) =
  - حالت `market_upper`: **صدک ۸۰ قیمت‌های معتبر بازار** (یک قیمت واقعی که در بازار وجود دارد → تخفیف باورپذیر و قابل دفاع)
  - حالت `markup`: `final × (1 + markup%)`
- تخفیف در بازه `[minDiscount, maxDiscount]` (۴٪ تا ۳۵٪) نگه داشته می‌شود؛ اگر تخفیف طبیعی کم بود base بالا می‌رود و اگر غیرواقعی بود پایین می‌آید.
- `discount% = (base − final) / base`

### قدم ۸ — انتخاب کمپین
کمپین‌های فعال بر اساس **اولویت** مرتب می‌شوند و اولین کمپینی که با (بازه تخفیف، ساعت، روز هفته، دسته) مطابقت دارد برچسب را تعیین می‌کند:
- **لحظه‌ای (flash)**: پیش‌فرض تخفیف ≥ ۱۲٪، اعتبار ۱۲ ساعت، اولویت ۱۰
- **منتخب / شگفت‌انگیز (featured)**: تخفیف ≥ ۳٪، اعتبار ۷۲ ساعت، اولویت ۵

در زمان‌های مشترک (هر دو فعال)، تخفیف‌های عمیق به «لحظه‌ای» و بقیه به «منتخب» می‌روند.

### قدم ۹ — امتیاز اعتماد و اعمال
```
confidence = 0.30·sellerScore + 0.30·validScore + 0.25·dispersionScore + 0.15·keepScore
```
- `sellerScore`: تعداد فروشنده نسبت به ۲×حداقل
- `validScore`: پیشنهادهای معتبر نسبت به ۲×حداقل
- `dispersionScore`: هرچه CV به ۱۵٪ نزدیک‌تر، صفر
- `keepScore`: اگر کمتر از نیمی از داده‌ها نگه داشته شد، مشکوک

اعمال خودکار فقط وقتی: `confidence ≥ 0.7` **و** هیچ دلیل بازبینی ثبت نشده **و** `autoApply` محصول روشن باشد. در غیر این صورت → **صف بازبینی** (`/review`) با نمایش کامل مراحل.

### قدم ۱۰ — بازبینی AI (اختیاری)
برای تصمیم‌های با اعتماد < ۰.۷۵، مدل زبانی به‌عنوان «تحلیل‌گر ارشد قیمت» نظر دوم می‌دهد: `approve | adjust | reject` + دلیل فارسی. رد AI = بازبینی اجباری.

## ۴. زمان‌بندی
- جدول `schedules`: بازه (دقیقه) + فیلتر دسته. زمان‌بند داخلی هر ۶۰ ثانیه سررسیدها را اجرا می‌کند.
- اجرای دستی: دکمه در UI یا `POST /api/runs {productIds?, category?}`.
- cron خارجی: `GET /api/scheduler/tick` با `Authorization: Bearer $CRON_SECRET`.

## ۵. اتصال به فروشگاه
Payload استاندارد:
```json
{ "sku": "...", "basePrice": 2490000, "finalPrice": 2429000, "discountPct": 2.4,
  "campaignType": "flash", "campaignEndsAt": "...", "decisionId": 12, "confidence": 0.83 }
```
- ووکامرس: `regular_price = base`, `sale_price = final`, `date_on_sale_to = campaignEndsAt`, متادیتای کمپین.
- وب‌هوک: `POST` با هدر `X-Pricing-Secret`.

## ۶. راه‌های بهبود (Roadmap)

### دقت داده
1. **خزش با مرورگر واقعی (Playwright + پروکسی مسکونی ایرانی)** به جای fetch؛ ترب رفتار مرورگر (JS challenge) دارد. لایه `humanize` آماده جایگزینی است.
2. **تطابق محصول با AI**: قبل از هر استعلام، عنوان لیستینگ ترب با نام/مشخصات ما مقایسه شود (رنگ، گارانتی، حافظه) تا قیمت مدل اشتباه وارد محاسبه نشود.
3. **نمودار قیمت ترب** (`price_chart`) برای تشخیص روند: اگر بازار در حال ریزش است، زودتر پایین بیاییم؛ اگر صعودی است عجله نکنیم.
4. **چند منبعی**: دیجی‌کالا/ایمالز به‌عنوان منبع دوم؛ مرجع نهایی = ترکیب وزنی منابع.
5. **اعتبار فروشگاه**: وزن بیشتر به فروشگاه‌های شناخته‌شده (لیست سفید با وزن ۱.۵) و وزن کمتر به فروشگاه‌های ناشناس.

### هوشمندی قیمت
6. **کشش قیمتی**: با اتصال داده فروش، برای هر محصول یاد بگیریم ۱٪ ارزان‌تر شدن چقدر فروش می‌آورد؛ اگر تأثیر ندارد، سود را نگه داریم (Bandit / A‑B روی زیرمجموعه محصولات).
7. **قیمت‌گذاری موجودی‌محور**: موجودی زیاد → تهاجمی‌تر؛ موجودی کم → نزدیک مرجع.
8. **ساعت‌های پیک**: در ساعات پرترافیک ترب، بازه استعلام کوتاه‌تر شود.
9. **Hysteresis**: اگر تغییر پیشنهادی کمتر از ۰.۵٪ است، اصلاً تغییر نده (کاهش نویز و به‌هم‌ریختگی قیمت در چشم مشتری).

### کنترل خطا
10. **تست‌های رگرسیون قیمت**: سناریوهای ثابت (۵ سایت اول قدیمی، لیستینگ ۲ فروشنده، کف غیرمنطقی) به‌عنوان unit test روی `runPricingPipeline`.
11. **هشدار تلگرام/ایمیل** برای صف بازبینی و خطاهای push.
12. **Rollback یک‌کلیکی** به تصمیم قبلی.
13. **درصد تغییر روزانه تجمعی** (نه فقط per‑run) تا چند اجرای پشت‌سرهم مجموعاً جهش نسازند.

### تخفیف
14. **چرخش هوشمند لحظه‌ای‌ها**: هر روز N محصول با بیشترین فاصله سود و بیشترین جستجو وارد «لحظه‌ای» شوند و بقیه «منتخب» بمانند.
15. **قیمت اصلی پایدار**: base را روزانه بیش از X٪ تغییر نده تا مشتری تخفیف را «مصنوعی» حس نکند.

## ۷. سناریوی نمونه (چرا این منطق کار می‌کند)
بازار: ۱۵ فروشگاه. ۳ فروشگاه اول با قیمت ۲.۱–۲.۱۵ میلیون اما ۱۸ تا ۳۰ روز بدون آپدیت؛ یک فروشگاه ۱.۹ (پرت پایین)؛ یک فروشگاه ۳.۲ (پرت بالا)؛ بدنه بازار ۲.۴۴–۲.۵۰.
- قدم ۲: سه قدیمی حذف. قدم ۳: ۱.۹ و ۳.۲ حذف.
- مرجع ≈ ۲.۴۶۵؛ کف معتبر ۲.۴۴؛ gap ≈ ۱٪ ≤ ۳٪ → رتبه اول: ۲.۴۳۹ → گرد: ۲.۴۳۹.۰۰۰
- base = صدک ۸۰ ≈ ۲.۴۹؛ تخفیف طبیعی ۲٪ < حداقل ۴٪ → base = ۲.۵۴۱.۰۰۰ → تخفیف ۴٪ → کمپین «منتخب».
- اگر ساده‌لوحانه کف خام (۱.۹) را دنبال می‌کردیم، ۵۴۰ هزار تومان ضرر در هر فروش داشتیم.
